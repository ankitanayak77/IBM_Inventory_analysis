# Normalized Power BI Analytical Datasets
## Smart Inventory & Sales Analysis System

This directory contains standardized, normalized, tabular CSV exports specifically structured for data modeling, DAX measure creation, and visual reporting in **Microsoft Power BI**.

---

## Analytical Architecture & Time Semantics

> [!IMPORTANT]
> **Data Semantics & Time Granularity Distinction:**
> 1. **Historical Sales Baseline (`2017-01-01` to `2018-09-30` / 638 Active Trading Days):**
>    Source transactional sales records cover this fixed historical timeframe. Metrics derived from this dataset (`units_sold`, `calculated_revenue`, `sales_velocity`) describe business performance across this historical observation period.
> 2. **Current Application Inventory State:**
>    Inventory stock levels (`stock_on_hand`, `stock_status`, `inventory_value`) represent the live operational state of the SQLite database across the 50 retail store locations &times; 35 products grid. **They are not projected backward as historical daily balances.**
> 3. **Calculated Revenue & Valuation:**
>    Historical sales transactions recorded units sold without itemized checkout prices. Revenue figures are explicitly **Calculated Revenue** evaluated at catalog retail selling price (`units_sold * selling_price`). Inventory valuation is calculated at retail catalog price (`stock_on_hand * selling_price`).

## Export File Specifications

### 1. `sales_daily.csv`
- **Description:** Daily transactional sales volume and calculated revenue aggregation.
- **Grain:** 1 record per calendar trading day.
- **Row Count:** 638 rows (covering `2017-01-01` to `2018-09-30`).
- **Source:** SQLite `sales` table (`GROUP BY sale_date`).
- **Schema & Columns:**
  | Column Name | Data Type | Description |
  | :--- | :--- | :--- |
  | `sale_date` | Date (`YYYY-MM-DD`) | Calendar transaction date. |
  | `units_sold` | Integer | Total units sold across all branches on this date. Total: 1,090,565. |
  | `transaction_count` | Integer | Total sales checkout transactions recorded on this date. |
  | `calculated_revenue` | Decimal | Calculated revenue (`SUM(quantity * selling_price)`). Total: $14,444,572.35. |

---

### 2. `sales_category.csv`
- **Description:** Aggregated sales volume, revenue, and transaction efficiency by merchandise category.
- **Grain:** 1 record per product category.
- **Row Count:** 5 rows (Art & Crafts, Toys, Games, Sports & Outdoors, Electronics).
- **Source:** SQLite `sales` joined with `products` (`GROUP BY category`).
- **Schema & Columns:**
  | Column Name | Data Type | Description |
  | :--- | :--- | :--- |
  | `category` | String | Catalog merchandise category. |
  | `units_sold` | Integer | Cumulative units sold across the 638-day historical period. |
  | `transaction_count` | Integer | Total sales transactions involving items in this category. |
  | `calculated_revenue` | Decimal | Calculated revenue generated by this category. |
  | `average_units_per_transaction` | Decimal | Average units per basket (`units_sold / transaction_count`). |

---

### 3. `product_movement.csv`
- **Description:** Empirical velocity metrics and 3-tier percentile movement classification.
- **Grain:** 1 record per active catalog product.
- **Row Count:** 35 rows.
- **Source:** `services.analytics_service` (`calculate_product_velocities`).
- **Schema & Columns:**
  | Column Name | Data Type | Description |
  | :--- | :--- | :--- |
  | `product_id` | Integer | Primary key of the product (1 to 35). |
  | `product_name` | String | Official commercial product title. |
  | `category` | String | Assigned merchandise department. |
  | `units_sold` | Integer | Total historical units sold. |
  | `transactions` | Integer | Distinct sales transaction count. |
  | `sales_velocity` | Decimal | Empirical velocity: `total_units_sold / 638 days` (units/day). |
  | `movement_status` | String | Relative percentile classification: `FAST MOVING` (&ge;66.43/d), `NORMAL`, or `SLOW MOVING` (&le;10.36/d). |
  | `current_stock` | Integer | Total physical stock currently on hand across all 50 stores. |
  | `reorder_level` | Integer | Network-wide reorder threshold (sum of branch reorder levels). |
  | `stock_coverage_days` | Decimal / Null | Approximate stock coverage: `current_stock / sales_velocity`. Null if velocity = 0. |

---

### 4. `inventory_snapshot.csv`
- **Description:** Detailed store-level stock snapshot and calculated inventory valuation.
- **Grain:** 1 record per store &times; product combination (Store-SKU).
- **Row Count:** 1,750 rows (50 stores &times; 35 products).
- **Source:** SQLite `inventory` joined with `stores` and `products`.
- **Schema & Columns:**
  | Column Name | Data Type | Description |
  | :--- | :--- | :--- |
  | `inventory_id` | Integer | Primary key of the inventory record. |
  | `store_id` | Integer | Foreign key referencing `stores` (1 to 50). |
  | `store_name` | String | Retail branch name. |
  | `city` | String | Mexican municipality where store operates. |
  | `product_id` | Integer | Foreign key referencing `products` (1 to 35). |
  | `product_name` | String | Product name. |
  | `category` | String | Merchandise category. |
  | `stock_on_hand` | Integer | Current physical units available at this branch. |
  | `reorder_level` | Integer | Branch reorder threshold trigger. |
  | `stock_status` | String | Stock condition: `NORMAL`, `LOW STOCK` (< reorder_level), or `OUT OF STOCK` (= 0). |
  | `inventory_value` | Decimal | Calculated inventory value: `stock_on_hand * selling_price`. |

---

### 5. `store_sales.csv`
- **Description:** Cumulative sales volume and revenue generation aggregated by retail branch.
- **Grain:** 1 record per retail store.
- **Row Count:** 50 rows.
- **Source:** SQLite `sales` joined with `stores` (`GROUP BY store_id`).
- **Schema & Columns:**
  | Column Name | Data Type | Description |
  | :--- | :--- | :--- |
  | `store_id` | Integer | Store unique identifier (1 to 50). |
  | `store_name` | String | Commercial store branch title. |
  | `city` | String | Store city location in Mexico. |
  | `units_sold` | Integer | Total units sold across all products at this location. |
  | `transaction_count` | Integer | Transaction count executed at this store. |
  | `calculated_revenue` | Decimal | Total calculated revenue generated by this store. |

---

### 6. `recommendations.csv`
- **Description:** Explainable, rule-based inventory replenishment signals and priority ranks.
- **Grain:** 1 record per catalog product.
- **Row Count:** 35 rows.
- **Source:** `services.recommendation_service` (`evaluate_product_recommendation`).
- **Schema & Columns:**
  | Column Name | Data Type | Description |
  | :--- | :--- | :--- |
  | `product_id` | Integer | Product identifier (1 to 35). |
  | `product_name` | String | Catalog product title. |
  | `category` | String | Merchandise category. |
  | `movement_status` | String | Classification from Phase 9 (`FAST MOVING`, `NORMAL`, `SLOW MOVING`). |
  | `current_stock` | Integer | Total units currently on hand across network. |
  | `reorder_level` | Integer | Aggregate reorder threshold. |
  | `sales_velocity` | Decimal | Units sold per day over 638 days. |
  | `stock_coverage_days` | Decimal / Null | `current_stock / sales_velocity` (approximate days cushion). |
  | `recommendation` | String | Decision-support signal: `PRIORITIZE REPLENISHMENT`, `REPLENISH SOON`, `MONITOR STOCK`, `REVIEW INVENTORY LEVEL`, `REPLENISH OR REVIEW`, `MAINTAIN CURRENT LEVEL`, or `MONITOR`. |
  | `reason` | String | Transparent business logic explanation justifying the recommendation. |
  | `priority` | String | Operational urgency tier: `HIGH`, `MEDIUM`, `LOW`, or `NONE`. |

## Power BI Import Recommendations
1. Open Power BI Desktop &rarr; **Get Data** &rarr; **Text/CSV**.
2. Select files from `exports/powerbi/`.
3. Set File Origin to **65001: Unicode (UTF-8)** and Delimiter to **Comma**.
4. Establish 1-to-Many relationships between `products.csv` / `product_movement.csv` and `inventory_snapshot.csv`, and between `stores.csv` and `store_sales.csv`.
